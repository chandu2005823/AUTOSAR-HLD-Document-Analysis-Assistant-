# Deployment preparation

This project keeps the existing React/Vite client and FastAPI service. These settings prepare deployment but do not create cloud resources or transfer local data.

## Vercel

Set the Vercel project root to frontend (the Git repository root contains the Document-Analysis-main project directory).

- Framework preset: Vite
- Install command: npm ci
- Build command: npm run build
- Output directory: dist
- Node.js: 22.12 or newer (the package engine range permits current 24.x)
- Environment variable: VITE_API_BASE_URL=https://<your-render-service>.onrender.com

The Vercel config rewrites application routes to index.html for React Router. The backend base URL must be the Render service origin without a trailing slash. The local Vite proxy remains available when VITE_API_BASE_URL is unset.

## Render

render.yaml describes a native Python web service with Python 3.13.2, the existing /health check, one instance, a 1 CPU / 2 GB plan, and a 5 GB disk mounted at /var/data. Its build command installs `requirements.txt` and explicitly pins `torch==2.14.0+cpu` and `torchvision==0.29.0+cpu` from the PyTorch CPU wheel index; its start command is `uvicorn backend.api:app --host 0.0.0.0 --port $PORT`. Applying it creates paid resources; review current costs and obtain explicit approval before syncing it.

### OCR runtime

`ingestion/pdf_parser.py` first extracts embedded PDF text with PyMuPDF. Pages with fewer than 20 alphanumeric characters are sent to RapidOCR, which is the primary OCR implementation. The pinned `rapidocr==3.10.0` package provides the ONNX model files; those files were present and validated during the existing local real-inference test. The primary OCR path does not require the Tesseract executable.

If RapidOCR is unavailable, errors, or returns no text, the parser tries its existing `pytesseract` fallback. `pytesseract` is only a Python wrapper: it does not install the Tesseract executable, and its availability is not guaranteed on Render's native Python runtime. The parser logs OCR failures and leaves the page text empty rather than fabricating extracted text; a scanned PDF may therefore have incomplete or no usable extracted content.

Local real OCR and scanned-PDF processing have been verified on Windows. Linux/Python 3.13 and Render OCR execution have not been verified, so this is not evidence that scanned-PDF OCR works on Render. No Tesseract installation is required for RapidOCR's primary path, but the fallback works only when the executable is separately available.

Set these values in the Render environment:

- AUTOARCH_API_SECRET: generated by the Blueprint; keep it stable. The service refuses to start if it is missing.
- AUTOARCH_REQUIRE_API_SECRET=true
- AUTOARCH_DATA_DIR=/var/data
- AUTOARCH_CORS_ORIGINS=https://<your-vercel-domain>
- GROQ_API_KEY: enter through Render's secret environment settings, never in Git.
- AUTOARCH_MAX_UPLOAD_MB=50
- AUTOARCH_OCR_DPI=300
- AUTOARCH_TEMP_DIR=/tmp/autoarch_ai
- HF_HOME=/var/data/huggingface

The default paths then place the access-control SQLite database, audit SQLite database, Chroma index, and processed artifacts below /var/data. The existing project-relative data/ tree is not copied into the container; this preserves local documents and avoids sending them to a build provider. Any later data migration needs a separate backup and approval. Keep one service instance while using SQLite and a disk-backed Chroma index.

After a service is deliberately created and approved, create the first administrator once against its mounted database with python -m database.access_control setup-admin. Do not run this against an existing production database without an approved backup and migration plan.

The Sentence Transformers model downloads on first use and is cached below HF_HOME. No model download or Groq request is performed by this preparation. The native Python runtime's ability to install the pinned ML dependency set has not been verified on Render; verify it with a Render build before deployment.

## Local checks

From the project root:

    npm --prefix frontend ci
    npm --prefix frontend run build
    npm --prefix frontend test
    $env:PYTHONDONTWRITEBYTECODE = '1'
    .\venv\Scripts\python.exe -B -m pytest -p no:cacheprovider tests/

The Node runtime must satisfy the Vite engine range. The backend tests use temporary paths for their database fixtures; inspect test outputs before using any other test suite that may touch local data.
